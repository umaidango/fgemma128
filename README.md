# fgemma128

**Fast Gemma 4 E2B on CPU, with a real 128K context — hand-written C.**

CPUで Gemma 4 E2B を動かすための推論エンジン（C言語、GGUF形式）。
スペック表の数字ではなく、**実際に使える128Kコンテキスト** を普通のCPUマシンで成立させることを目標にします。テキストに加えて、vision（画像）と audio（音声）の入力にも対応します。

- 対象モデル: `google/gemma-4-E2B-it`
- 形式: GGUF（重み・メタデータ・トークナイザが1ファイル）
- 最初の対応ファイル: 公式QAT版 `google/gemma-4-E2B-it-qat-q4_0-gguf`（Q4_0はブロック構造が最も単純なため）。参照用にQ8_0、後段でQ4_K_Mへ拡大
- ライセンス: MIT（[LICENSE](LICENSE)）
- 技術調査: [docs/RESEARCH_MEMO.md](docs/RESEARCH_MEMO.md)（アーキテクチャ実値、KV計算、ボトルネック分析）

## 特徴（目指す姿）

- **本物の128K**: E2Bは MQA（KVヘッド1）・層間KV共有・sliding window により、正しく実装すれば128K時のKVキャッシュは fp16 でも約774MiB。容量ではなく prefill の再計算回避と長文脈 decode の帯域設計で勝負する
- **CPU専用・依存最小**: GPUもフレームワークも使わない。Cと標準的なOS機能だけ
- **マルチモーダル**: テキスト → 画像（vision tower）→ 音声（audio tower）の順に対応を広げる
- **再現可能なベンチマーク**: 測定条件（マシン、スレッド数、量子化、文脈長）を必ず併記し、誰が回しても同じ数字になる形で公開する

## なぜ作るのか

1. **技術として**: 「小さいモデルなのに長文脈の運用が未整備」という隙間がある。llama.cppは最強の汎用実装だが、E2B専用・128K運用専用に絞ればまだ設計の余地がある（詳細は調査メモ）。
2. **人として**: これは参加する人間のプログラミング技能を鍛えるプロジェクトでもある。そのため次のルールを置く。

## 先行プロジェクトとの違い

- **llama.cpp**: 汎用で最強の実装であり、本プロジェクトのベンチマーク基準。汎用性では勝負しない
- **gemma4.c**（Ryan Senn）: 約700行の純C実装で、短文脈では既に速い。本プロジェクトの新規性は「純Cで動く」ことではなく **128Kの実運用とマルチモーダル対応** にある
- **kimi-k3-in-c**: 着想源。手法（MoEの疎さ）は dense な E2B には使えないが、「疎なものは常駐させない」「全条件で出力一致を検証する」「ベンチの前提を正直に書く」という姿勢は借りる

## ロードマップ

計画（このロードマップの維持・詳細化）はAIアシスタント側の担当、実装は人間が担当する。

| 段階 | 内容 | 合格条件 |
|---|---|---|
| M0 | GGUFローダ（ヘッダ/メタデータ/テンソル情報）+ テンソルダンプ | 層別の形状表が確定（double-wide MLPの範囲、共有層に attn_k/v が無いこと、PLE形状） |
| M1 | スカラー版 forward（1トークン、Q4_0/Q8_0の逆量子化込み） | llama.cpp（同じGGUF）と top-1 トークン一致、hidden の cosine ≒ 1.0 |
| M2 | KVキャッシュ（層間共有 + sliding window）で複数トークン生成 | 1K文脈で参照実装と一致 |
| M3 | Q4_K 対応 + GEMV最適化（SIMD）+ スレッド化 | 短文脈で llama.cpp と同等以上 |
| M4 | 長文脈: チャンク prefill、KV量子化、state 保存/再開 | needle テスト 32K / 128K 合格、再開が再計算より桁で速い |
| M5 | PLE ストリーミング、RSS仕上げ、ベンチ整備 | 再現可能なベンチマーク一式が揃う |
| M6 | **Vision**: 画像入力（vision tower + プロジェクタ、mmproj GGUF） | 画像つきプロンプトで参照実装と一致 |
| M7 | **Audio**: 音声入力（audio tower） | 音声つきプロンプトで参照実装と一致 |

判定基準（どこで「勝った」と言い、どこで見切るか）は調査メモ §11。スター数は需要とみなさない。
